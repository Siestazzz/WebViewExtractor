# Generic v10: reserve measured report export time

V9 retained valid partial reports, but Sohu reached 600.034 seconds and the external watchdog killed it; FreeReels timed out inside the supervisor. Sohu's detailed JSON reached roughly 286 MB. The prior worker could keep analyzing until its entire time budget elapsed and then build/export the final three reports, followed by supervisor parsing/exporting those reports again.

The worker now measures complete checkpoint construction and three-file export. Before each deep epoch it subtracts `2 seconds + 3 × maximum observed checkpoint export duration` from the remaining worker deadline. Epoch duration cannot exceed that remainder; when none remains, it stops scheduling deeper work and emits the final partial report. The maximum is monotonic, so a later cheap checkpoint does not erase evidence of expensive serialization. Report metadata records the reserve and largest observed checkpoint duration, and unfinished analysis ending for this reason uses `scheduling_stage=report_reserve`.

This reduces time available for traversal to pay for actual reporting costs. It is not claimed as analysis acceleration or quality completion. CPU/heap limits and supervisor/external deadlines are unchanged. Individual non-cooperative jobs may still exceed an epoch boundary, and unexpectedly rapid report growth can exceed the estimate; the watchdog and last atomic report remain necessary. Ten-App large-report measurements are required before claiming the hard limit is satisfied.

ReportBudgetFixture verifies a four-second observed export leaves fourteen seconds for finalization, prevents another epoch inside that window, retains worst-case cost, and handles expiry/overflow without reopening the analysis budget. It is included in capabilitySelfTest. The changed Main and helper compile independently against the frozen v9 API; integrated tests and real-App runs follow once the concurrent implementation work is frozen.
