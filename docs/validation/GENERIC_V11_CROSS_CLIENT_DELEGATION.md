# Generic v11: actual same-signature delegation across Client contracts

Independent News source review found an installed Chrome client's `onReceivedTitle(WebView,String)` calling the same complete signature on an actual field-held custom WebViewClient. That destination method is not a standard WebViewClient callback. The prior extractor rejected it solely because the destination's SDK family did not declare that member, despite the actual installed Chrome callback forwarding to it. Source evidence is recorded in `news/generic-v9-ysp-and-title-source-diagnostics.json`; the existing four source expectations remain unchanged.

The generic rule recognizes a virtual/interface call whose full method shape equals the source's actual standard Client callback shape. It is active only while traversing an installed Client context. Receiver evaluation and actual virtual resolution still apply, and only concrete object/new/view identities with an implemented target are accepted. The delegated fact retains the installed Client identity, destination object identity, actual WebView argument, call site and binding evidence. A different destination SDK family is allowed because the invocation itself proves the forwarding relationship. No App name or private method signature is encoded.

Indexing marks these forwarding sources as relevant to installed-client traversal. Reporting includes only the called destination member and same-signature explicit super implementations, not every method on the delegate. Existing standard-contract delegation remains supported. Arbitrarily named helper callbacks are not generalized by this rule, and unknown object receivers remain unresolved.

`CrossClientDelegationFixture` installs two Chrome wrappers holding distinct WebViewClient-derived delegates on two WebViews. Both forward the exact title signature. A third uninstalled wrapper and an invalid source overload must not activate delegates or unrelated page-finished callbacks. The same test fails on the frozen v10 jar with no delegated facts; the isolated new implementation passes and preserves both object identities. Logs are `test/runs/generic-v11-cross-v10-repro.log` and `test/runs/generic-v11-cross-test.log`. Integrated tests and ten-App effect measurement remain required before claiming the real four missing expectations are fixed.
