# Ordinary conditional initialization

Source audit identified an actual XML WebView constructor calling init(false), but the v6 report attached an intercept Bridge to that same XML receiver. Evidence is preserved in sohuvideo/generic-v6-init-false-capability-precision.json; the implementation does not match its private class names.

ConditionalInitFixture reproduces the generic issue with a shared private configure(boolean), separate true/false allocations and an actual XML constructor. Frozen v7 incorrectly emits the Bridge for the direct false instance. The fix enables numeric/boolean IF summary refinement, previously limited to instanceof and switch shaped methods. Base decoding retains guard probes. Ordinary IF-only methods are specialized only when the actual context resolves a previously nonconstant operand to a numeric/boolean constant; unknown conditions reuse the conservative base summary. Existing 500-instruction and16-variant limits remain, including budget diagnostics and conservative fallback. Mutable fields still cannot prove invariant guard values.

The fixture proves the XML constructor is actually traversed via a separate unconditional operation, and tests that unknown guards preserve branches without consuming a specialization. A true allocation remains a positive; false direct and XML receivers must have no Bridge. Frozen v7 failure and current success are in test/runs/conditional-init-v7.log and conditional-init-fixed.log. Real App precision/recall changes require the next frozen iteration; smaller fact counts alone do not establish improved precision.
