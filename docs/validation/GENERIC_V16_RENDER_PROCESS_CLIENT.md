# v16 standard renderer callback contract

Independent source review found a missing public SDK family: a registered WebViewClient's onPageFinished installs a WebViewRenderProcessClient through a synthetic static forwarding method. Evidence is retained in freereels/vungle-webview-render-process-client-family-source-proof.json and its Markdown companion. This motivates a general SDK contract, without matching an App or SDK implementation name.

Android's [public renderer client contract](https://developer.android.com/reference/android/webkit/WebViewRenderProcessClient) defines two API-29 callbacks: onRenderProcessResponsive(WebView, WebViewRenderProcess) and onRenderProcessUnresponsive(WebView, WebViewRenderProcess), both returning void. The platform WebView setter has both a one-client-argument form and an Executor/client form; see [platform WebView source](https://android.googlesource.com/platform/frameworks/base/+/refs/heads/android11-release/core/java/android/webkit/WebView.java).

SdkClientContracts recognizes the exact platform WebView owner family, complete parameter descriptors and void result. CapabilityIndex recognizes the renderer client hierarchy and the two complete virtual method signatures. Existing actual-call propagation handles static wrappers. Callback binding takes the final declared parameter of a standard setter, so an Executor is not mistaken for the installed client; custom receiver-field registration retains its original parameter convention. Existing inherited-member enumeration and registered-client body traversal apply. A similarly named method with Object parameters is not recognized.

RenderProcessClientFixture covers direct installation, Executor overload, synthetic-style static forwarding, inherited implementations, exact receiver identity among two allocated WebViews, null removal, wrong setter signature and an allocated-but-uninstalled client. Extra overloads/helper methods are excluded from the member surface. The complete capabilitySelfTest/compactReportTest/shadowJar suite is required before freezing the release.

Limits: this addition models the platform android.webkit contract. It does not establish dedicated AndroidX WebViewCompat renderer-registration semantics. Synthetic tests do not prove the real Vungle host chain is reached within the App budget; the expanded v16 oracle contains the independently verified registration and two members for that check. Real-App results must come from the new ten-App run, never from this fixture.
