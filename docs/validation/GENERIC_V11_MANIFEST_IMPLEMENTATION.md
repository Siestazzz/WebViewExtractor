# Generic v11 application metadata module reflection

This model uses the public Android metadata acquisition protocol and actual arguments. It adds no application name, module key, selector value, interface name, or capability root. Source evidence is `sohuvideo/qf-manifest-bridge-source.json`; the evidence establishes a real Context → PackageManager → current package / GET_META_DATA → ApplicationInfo.metaData → Bundle iteration → value filter → Class.forName(key).newInstance → retained module → init(actual WebView) chain. The implementation has not yet been validated against the frozen ten-APK v11 run and does not claim recovery of that application.

## Scope and binding

`ApkInventory` retains typed application-level manifest metadata. Activity metadata is excluded. String values remain strings; resource references remain unresolved rather than becoming selector literals. Acquisition requires an actual current Activity host or allocated Application object, matching current APK package name, and a known flag containing GET_META_DATA (0x80). Unknown Contexts, arbitrary ContextWrapper instances, foreign package requests and absent flags do not acquire metadata scope. Full return/parameter shapes on Context and PackageManager subtypes are recognized. Application-defined override bodies are not bypassed.

A method must actually read ApplicationInfo.metaData and call Bundle.keySet, Class.forName and Class.newInstance to receive per-entry contexts. Each context binds the same scoped Bundle, key and typed value. A metadata value equality/type guard is folded only when its operand carries that entry's metadata origin. ForName receives the actual selected key, resolves only an existing class, and reflection constructs only a public concrete class with a public no-argument constructor. The resulting normal object participates in ordinary constructor, retained-field/static-cache and interface-call propagation, so capabilities are attached only when the actual module method receives the actual WebView. Entry contexts are scoped to their consumer method; a nested consumer enumerates its own entries. Installed-client context tokens remain last in the job arguments.

The generic literal-Class reflection helper is separate (`GENERIC_V11_REFLECTIVE_FACTORIES.md`). Metadata origin controls metadata-derived Class values, while ordinary actual Class literals can use that helper. No module is instantiated merely because it appears in the manifest.

## Bounds and uncertainty

Existing 500-instruction summary refinement and 16-variant per-method limits remain unchanged. Enumeration uses the existing collection-style limit of 256 entries and cooperative analysis deadline checks. Native metadata return expressions are kept intact only in actual consumer methods, allowing scoped semantic folding before the normal expression-depth cutoff; other methods keep the existing depth limit. Metadata resolution itself is bounded to 12 expression levels. Unknown/resource values, unresolved classes, missing public constructors, unknown acquisition scope, incomplete summaries, entry/deadline limits and ordinary summary-refinement exhaustion remain diagnostics or conservative unknowns. Nonempty iterator hasNext remains unknown to avoid pretending the analysis executes a real iterator to termination. Empty inventory folds to false.

The model currently requires acquisition and enumeration/reflection to be visible in the same consumer summary. It does not solve arbitrary distributed iterator pipelines, runtime external package metadata, resource-string resolution, unknown Class names, inaccessible construction or service map correctness beyond separately tested keyed registry structures. Allocated Application provenance is a conservative APK-local abstraction, not a proof of runtime attachment.

## Validation

`ManifestModuleFixture` builds binary AXML and DEX: actual current-package GET_META_DATA iteration, selector equality, reflective noarg construction, static module cache, and later interface init bind four isolated WebViews across two Activity heaps. Negative hosts cover no flags, foreign package and uncalled loader. Wrong metadata value, activity-only metadata, private constructor and unresolved class do not inject. Direct boundary checks cover inherited Application getter identity, wrong overload, explicit application override, unknown Context, resource metadata and empty iteration. Existing component/lifecycle, client isolation, conditional-init, reflection transport, parallel analysis and refresh tests run in the complete capability self-test.

`ManifestExpressionDiagnosticFixture` previously demonstrated the frozen v9 expression-depth break at Class.forName/newInstance in an equivalent public protocol. This is a structural diagnostic, not an APK recall score. The v11 full suite additionally runs `ReflectiveFactoryFixture` and the twelve actual reflective service constructor regressions; known old direct-allocation missing-key errors are not reported as passing negative tests.
