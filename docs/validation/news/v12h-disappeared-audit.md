# v12h disappeared-capability source audit

This is a non-blind development audit of the seven hosts whose v12a semantic tuples decreased in v12h. It does not alter `canonical-facts.jsonl`, and it does not treat prior host ownership as proof that every old tuple was correct. Replayable confirmed facts are in `v12h-disappeared-development-facts.jsonl`; `build_v12h_disappeared_oracle.py` regenerates them from the frozen v12a report after applying the source-confirmed component and site allowlist.

The CaptureDetailPage component internals are source-confirmed, but the representative `ShellActivity` host binding is pending. Inside the component branch, k2 option 107 calls `CaptureFullContentShareDialogHelperKt.ʾʾ(Context,ShareData,int)`. The helper resolves `CaptureWebViewService.ʻ(Context,Item,String,IDetailModel,int,Function2)`, whose normal branch constructs `CaptureDetailPage` with the same Context and calls `setData`. `setData` invokes `initWebView`; that method acquires one `NewsWebView`, installs `CaptureDetailPage$b` and `QNWebChromeClient`, applies the captured settings, and stores the receiver in `webView`. The completion callback adds the page View to `CaptureFullContentView`, which is then rendered into the visible capture UI. The 15 settings and 11 concrete client overrides are valid once the component is invoked, but no Shell path to k2 selector 107 was proven; they are not positive Activity facts.

The KK-only capture bridge component is source-confirmed, while its `KkAlbumDarkModeActivity` binding is pending because the proven share listeners select 3/4 rather than 107. `NewsDetailFloatViewJavaScriptServiceImpl.ʼ(Object,b,f)` returns `new com.tencent.news.ui.visitmode.webview.j((a)detailPage,...)`. `CaptureDetailPage.loadUrl` stores that service result as `floatCardInterface` and invokes `webView.addJavascriptInterface(floatCardInterface,"TencentNews")` on the same stored field.
