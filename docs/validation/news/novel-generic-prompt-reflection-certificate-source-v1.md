# Generic prompt reflection certificate, source v1

This is a development source review, not an analyzer-output comparison, holdout or new positive oracle. APK SHA256: `c4a8d2904ec530a4b97d8dbd04cd641f175918f24cff5d056d216e3808852941`. The companion JSON binds every source file SHA and source range. Its SHA256 is `407fc9d7e39e4fa6ecd957972def24cf5fa00fcf02446633461cc9bd0acd7c5a`.

A generic recognizer must prove the complete object chain before considering public members: actual WebView installation → concrete client → captured router → concrete script target → message-derived selector arrays → public method lookup → invocation of the returned Method with the same target and argument array. Package names and class names in the evidence annex are observations, never rule predicates. A sibling allocation of the same class is insufficient.

The observed Novel chain retains the nested actual AdWebView, constructs a Novel script against it, and installs Activity.e/f clients with that script. The Chrome superclass retains JavascriptBridge. Its final `interfaceObj` field holds this same script. The effective inherited `onJsPrompt(WebView,String,String,String,JsPromptResult)` calls promptCall with message and URL when result is nonnull. This entry has no URL/prefix/defaultValue selector gate; rate and hotpatch checks remain conditions. There is no native injected registration name: `registration_name=null` means not applicable. The separate DT native injection must retain its own identity.

`call` reads JSON method/types/args/instanceName. Both arrays have N=types.length and are populated with the same loop index. The lookup is `interfaceObj.getClass().getMethod(method, classes)`. The actual sink passes that returned Method, the same `interfaceObj`, and the populated arguments to the monitoring wrapper. Its ordinary branch calls `method.setAccessible(true)` and `method.invoke(obj,args)`. The wrapper also has replacement logic, so merely seeing a call to it does not prove unconditional forwarding. Its packaged registry has 46 declaring-class keys, none in this script hierarchy. This supports the ordinary packaged branch, with dynamic registry mutation/hotpatch behavior explicitly outside the proof. Async mode separately captures the same Method and argument array; the runnable reads the enclosing router's final target field. Prompt mode executes synchronously.

The only populated parameter classes are exact String, primitive int, primitive boolean and JSONObject. A function token constructs an out-of-band JavascriptCallback but populates neither Class nor argument slot. Unknown tokens similarly leave slots unset; neither case permits public-member widening. Malformed JSON and conversion errors reach error handling. A null lookup enters CommonAbility fallback, whose registry/initialization is independently unresolved; it does not prove invocation of the named Java member.

There is no argument-array length equality guard. Extra JSON arguments are ignored. Missing nullable string/object positions can become null because Android JSONArray.isNull treats a missing index as null; numeric/boolean/function indexed getters may fail. The parameter Class still remains String/JSONObject for null values. See [Android JSONArray.isNull](https://developer.android.com/reference/org/json/JSONArray#isNull(int)).

The negative annex contains all 61 packaged public declarations with at least one parameter outside the parser's exact Class domain. They are unreachable through this particular selector route, not globally unreachable Java methods. Their exact signatures and source hashes are retained. Nonpublic members and constructors also cannot be selected by this public-method route. Conversely, public unannotated, static and synthetic members cannot be discarded by labels alone: there is no JavascriptInterface annotation or instance-only guard. The separately proven static synthetic String forwarder is eligible. Return types do not participate in getMethod selection. Covariant/bridge duplicates require precise effective-method resolution; no real covariant case is claimed by this review. Novel's actual setStatusBarColor(int) override suppresses the parent implementation because it does not call super.

The proposed minimum implementation boundary is a certificate carrying installed WebView/client allocation provenance, target-field identity, entry/protocol conditions, selector slot conversions, exact lookup relation and actual invocation forwarding. Emit only members satisfying that certificate and preserve unresolved conditions. Do not recursively scan public members, turn unknown types into wildcard parameters, or infer transport identity from a class name. A callback registration or valid Activity ownership is independent of this transport capability proof.

Recommended generic negative fixtures cover an uninstalled client, same-class different script instance, lookup on one target/invoke on another, unknown/function type slots, unsupported parameter types, malformed input, missing numeric argument, replacement wrapper, empty override and shadowed parent method. Positive fixtures should cover nullable string/object slots, ignored extra args, inherited public methods, most-derived overrides, ordinary static methods, a public synthetic forwarder and preserved async capture. Fixtures must use synthetic class names and exact platform APIs. This document does not assert those fixtures or a production implementation have run.
