Three public SDK Activity ownership chains now have fresh hash-bound source evidence. Each reaches BaseWebActivity with its actual this, constructs the same client/binding, receives the retained BaseWebView through the binding callback, and attaches it through the adapter lifecycle. This is a development audit; overlap with legacy unavailable holdout membership is unknown.

Whole-host closure remains partial. The shared superclass actively registers nine custom JS modules; Transparent replaces the UI module with a subclass carrying NewJavascriptInterface annotations. BaseWebView also registers an Android-annotated preload bridge and installs a Chrome proxy even when its API argument is null. Pool settings, actual callback/delegate members and transport registry rules must be enumerated before these hosts can count as deep-complete.
