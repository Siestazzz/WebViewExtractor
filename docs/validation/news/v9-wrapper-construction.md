# v9 nested wrapper construction for WebNovel and WebAdvert

The five settings remain tied to real objects. The missing relation is a nested XML construction chain, not a generic `field_object` seed.

For the novel path, either `NovelWebView(Context)` or `NovelWebView(Context,AttributeSet)` synchronously calls `init(Context)`. That method inflates its child layout, assigns `mLoadingWebView` from `findViewById`, and copies `mLoadingWebView.getWebView()` into its `mWebView` field. `NovelLoadingWebView` has Context, Context/AttributeSet, and three-argument constructors. The first two delegate to the three-argument constructor; that constructor calls `initialize(Context)`. `initialize` inflates another layout and assigns `mWebView = (BaseSysWebView)findViewById(...)`. There is no `new BaseSysWebView` and no `onFinishInflate` assignment. The platform LayoutInflater constructs the XML WebView before `findViewById` returns it, so the BaseSysWebView constructor settings occur before the field assignment.

For the advert path, both `WebAdvertView` constructors call `init(Context)`, which inflates its child layout and assigns `mLoadingWebView`, then `mWebView = mLoadingWebView.getWebView()`. The three `AdLoadingWebView` constructors converge on the three-argument constructor and `initialize(Context)`. After inflating its inner layout, initialization uses one of two branches: if a `ViewStub` exists, it assigns the result of `ViewStub.inflate()` cast to `AdWebView`; otherwise it assigns an existing `AdWebView` found by ID. Neither branch invokes an app factory or explicit `new`. Both are XML LayoutInflater paths. `AdWebView` extends `BaseSysWebView`, and all four of its constructors directly invoke a BaseSysWebView constructor, which applies the shared settings before returning.

The earliest relevant trigger is therefore the outer custom View constructor reached from the Activity layout. Analysis must then follow the outer synchronous inflate into the nested wrapper constructor, follow that wrapper's synchronous inflate or `ViewStub.inflate`, and preserve the exact field/getter identity. Seeding the outer cast alone does not expose the inner WebView constructor effects unless these inflation edges are modeled.

All constructor, initializer, getter, and field descriptors in the JSON companion were checked against the APK DEX symbol export. No `onFinishInflate` override exists in any of the four wrappers.
