# Loading/RainbowBridge rule review

RainbowBridge is a facade over one process-wide `NativeMethodInjectHelper` instance. `RainbowBridge.clazz(Class)` delegates to `NativeMethodInjectHelper.clazz(Class)`, which only appends the class to `mInjectClasses: List<Class<?>>`. Registration becomes active only when `NativeMethodInjectHelper.inject()` runs. The active structure is `mArrayMap: Map<String,Map<String,Method>>`; the outer key is exactly `Class.getSimpleName()` and the inner key is `Method.getName()`.

The complete exposure predicate comes from `putMethod(Class)`. It enumerates `Class.getDeclaredMethods()`, so inherited methods do not qualify. A method must be both public and static and must have exactly four parameters whose class identities, in order, equal `WebView`, `JSONObject`, `JsCallback`, and `Handler`. No annotation is required, and return type is unrestricted. Instance methods, non-public methods, inherited methods, and methods with merely assignable parameter types are excluded.

Commit behavior matters for sound extraction. `inject()` with no pending classes does nothing and preserves the prior active map. With at least one pending class it clears the entire active map, processes pending classes in order, and clears the pending list afterward. `putMethod` replaces the whole entry at `cls.getSimpleName()`, including with an empty method map. Two different classes with the same simple name therefore collide, and the later class wins. These are replacement semantics, not an accumulating global union.

The runtime lookup is `findMethod(className,methodName)`. `JsCallJava` parses the `rainbow` URI: URI host supplies the simple-name namespace and the slash-stripped path supplies the method name. It invokes the selected static method as `Method.invoke(null, webView, JSONObject, JsCallback, Handler)`.

For `LoadingWebActivity`, host attribution requires the concrete lifecycle chain. `LoadingWebActivity.getFragment()` returns `CommonWebFragment.newInstance(url)`. `FragmentWebLoadingBase.initView(View)` creates a `TimeoutCheckWebView`, stores it in `mWebView`, and calls `mWebView.setWebChromeClient(getWebChromeClient())`. Virtual dispatch selects `CommonWebFragment.getWebChromeClient()`, so `CommonWebFragment$1.onJsPrompt(...)` is installed on that same `mWebView`. `CommonWebFragment.initView(View)` first calls the superclass initialization and then `initjsinterface()`. Its prompt callback passes the callback's WebView, the enclosing Activity's handler, and prompt message argument 2 to `JsCallJava.call`.

`initjsinterface()` registers only while the enclosing Activity stack size is one. With no `method_class_names` extra it executes `RainbowBridge.clazz(JSCommondMethod.class).inject()`. With the extra present, it splits the value on `&`, adds the fully-qualified `JSCommondMethod` name if absent, applies `Class.forName` and `clazz` to every successfully resolved name, then calls `inject`. A `Class.forName` failure is caught and skipped.

An implementation must therefore require a host execution path through `LoadingWebActivity.getFragment -> CommonWebFragment.initView -> initjsinterface -> clazz -> inject`. Finding `JSCommondMethod`, or another compatible class, anywhere in the APK does not prove that the current Activity registered it. It must also bind `CommonWebFragment$1` to the same `mWebView` created in the superclass initialization. For unresolved intent class names, retain one dynamic-class registration fact and do not invent endpoint members from unrelated APK classes. If the stack-size condition prevents registration, singleton state left by an earlier Activity may still answer lookups, but that is inherited process state rather than a new registration by the current host.
