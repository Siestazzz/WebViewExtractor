# Public annotated static Java bridge methods

The source-frozen full SDK extension finds six public static @JavascriptInterface methods per reviewed Sohu SDK host: NBSJavaScriptBridge.logJsError/logJsResult/logRes/postMessage and NBSJSBridgeDom.logDebug/postMessage. Actual registered NBSWebViewClient.onPageStarted injects both concrete bridge objects (lines 77-78). SohuWebView does not swallow addJavascriptInterface, and the initial client calls super.onPageStarted; the Close client inherits that callback. These are valid conditional registrations. All six source signatures and annotation locations are preserved in shared-sdk-surface-source.json.

The v3 evaluator misses exactly these six methods on each of 26 reviewed hosts (156 facts), while matching the instance methods. CapabilityEngine.bridgeMembers excludes access flag 8 before annotation testing. Public static annotated methods are supported by Chromium's Java bridge: its invocation helper selects the class for a static method and issues CallStatic JNI calls. [Chromium primary implementation](https://chromium.googlesource.com/chromium/src/+/2f38a9ff1e78023cc3fa341a30448d1b9ca5a891/content/browser/android/java/gin_java_method_invocation_helper.cc) directly demonstrates this dispatch.

Minimal generic case: register new Bridge() under a literal name, where Bridge declares public static @JavascriptInterface void send(String). The exposed-member inventory must include send. A private static method or an unannotated public static method under targetSdk>=17 remains excluded. This correction belongs to the public bridge contract and must not depend on instrumentation package names.
