# Reuse field lookup indexes across binding refresh calls

The v7 shared-graph memo fixes a long recursive computation but introduces extra cost on some hosts. Tencent News v6→v7 external wall time rises124.1→259.7 seconds while index time stays51 seconds and decoded/refined/discarded-context counts are unchanged. NewsDetail and PushDetail analysis grow roughly11 seconds each to72/70 seconds. The repeated dynamic-receiver dependency path rebuilds a full field index per top-level refresh. This is an observed cost regression plus a code-level mechanism; actual speed recovery remains to be measured.

FieldHeap builds an index only for requested field identities, retains exact receiver keys, and reuses it for later refreshes on the same host. Writes, replacement, compute/merge, remove and clear update or invalidate that index. The first scan checks the existing analysis deadline. Entry views reject direct mutation that could bypass index maintenance. No cached binding result survives heap writes: only the current field-value index is reused; the path/depth-sensitive refresh memo remains invocation-local. Completed hosts release both heap and index together.

FieldHeapFixture verifies indexed values through mutation sequences and forbids entry mutation; RefreshBindingFixture still passes its80 seeded cyclic semantic equivalence cases and dynamic receiver/heap-mutation checks. No analysis time/context/depth limit is increased. Engine edits are limited to the Host heap type and the existing dynamic dependency lookup; this change is separate from reflective transport work.
