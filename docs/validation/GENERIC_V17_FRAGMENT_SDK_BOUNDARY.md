# Exact modeled Fragment SDK bodies

The frozen v15 Xigua Browser queues contain SDK Fragment state transitions and substantial unrelated initialization. These hosts remain in phase 1, so missing capabilities do not establish a semantic break. The evidence and report hash are retained in xigua/v16-browser-runtime-budget-review.json and its companion Markdown.

Previously the engine modeled manager getters, beginTransaction, and show return identities, while their calls still entered ordinary relevant-method dispatch. Activity seeding also independently enqueued relevant inherited SDK manager getters. The v17 change consumes those exact public contracts once the actual receiver is known compatible and dispatch resolves to an approved SDK declaration. It excludes the inherited modeled SDK getter from independent Activity roots. Transaction add/replace/remove/commit already had a separate terminal model. Unsupported FragmentManager methods continue through ordinary processing.

Application overrides retain actual body execution. Explicit super calls can use the modeled SDK declaration, while virtual dispatch to an application override cannot. Unknown or incompatible receivers do not fabricate manager identities or installed Fragments. Transaction identity values now qualify as known receivers for the exact fluent show contract; compatibility still checks the declared SDK type.

FragmentSdkBoundaryFixture adds a harmless StateMachine.tick helper to packaged SDK getter/begin/show bodies and forces ordinary relevance for those methods. It verifies the helper is never visited, while the actual installed Fragment still yields bridge, setting, and callback categories. An application getter override installs a real bridge before returning null; that bridge must remain. Uncommitted and allocated-only Fragments remain inactive. Existing three-family explicit-super, application-null, transaction isolation, and manager constructor capture fixtures remain enabled.

This is a semantic boundary for the modeled public SDK contracts, not a claim that arbitrary packaged implementations have no side effects. A modified SDK declaration that performs additional application-defined capability effects would exceed the model. No broad AndroidX namespace or unsupported state-machine method is skipped. Same-site abstract transaction merging and unsupported Dialog/XML/navigation installation retain their documented limits.

The first two verification runs caught independent getter seeding and missing transaction-kind acceptance for fluent show; those failures are preserved in generic-v17-sdk-boundary-tests.log and generic-v17-sdk-boundary-tests-2.log. Final validation is recorded separately in generic-v17-sdk-boundary-final.log. Actual ten-APK measurements are required before claiming a performance or recall improvement.
